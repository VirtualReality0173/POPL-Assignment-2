P2 – Arithmetic Equation Generation

Prompt 1 – Expression Evaluator

Implement an expression-tree evaluator using the representation
num(N) and op(Operator, Left, Right).

Support +, -, *, and exact integer division.
Reject division by zero and non-exact division.
Allow negative intermediate results.
Invalid expressions must fail cleanly.
Do not use string parsing, global variables,
assert, or retract.


P2.a – Generate One Valid Arithmetic Equation
We are implementing P2 of the CS F301 Principles of Programming Languages assignment using SWI-Prolog 9.x.
Implement generate_equation(List, Equation) in code/43_q2.pl.
The predicate must generate one valid arithmetic equation using every number in the input list exactly once and in the original order.
Requirements

Split the input list into two nonempty consecutive parts, representing the left and right sides of the equation.
Generate all possible binary expression trees for each part, preserving the original number order.
Support the operators +, -, *, /.
Parentheses may be used to represent different expression trees.
Both expressions must evaluate to the same integer.
Division is permitted only when the divisor is nonzero and the division is exact. This restriction applies to every intermediate division.
Negative intermediate values are allowed.
There is no unary minus.
Return the equation as an SWI-Prolog string, not an atom or character list.

Format expressions according to the assignment's canonical rules:

* and / have higher precedence than + and -.
Operators are left-associative.
Parenthesize a left operand only when its precedence is lower than its parent's.
Parenthesize a right operand when its precedence is equal to or lower than its parent's.

Numbers are never parenthesized.

If no valid equation exists, including for lists of length zero or one, the predicate must fail cleanly without looping or raising an error.

Implementation constraints

Do not use assert, retract, or global variables.
Do not construct an expression string and parse it back to evaluate it.
Allowed libraries: lists, apply, yall, aggregate.
Do not print anything.
Use recursive predicates and expression trees.
You may create helper predicates needed by generate_equation/2.
Do not implement all_equations/2 or count_equations/2 yet.

Expression representation
Use:

num(N) for a number.
op(Operator, Left, Right) for a binary expression.

Testing
Verify:

generate_equation([4,2,5,3], E) returns one of the seven valid equations specified in the assignment.
generate_equation([2,3,4], E) fails.
generate_equation([2,4,8], E) returns "2*4=8".
Empty and single-element lists fail cleanly.

Return the complete P2.a implementation and a brief explanation of the helper predicates. Do not implement P2.b.
